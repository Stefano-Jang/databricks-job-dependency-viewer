# JIIG Software Requirements

## Product objective

When a Databricks Lakeflow Job or Pipeline fails, JIIG must help an operator identify downstream data-product exposure and the owners who need to act without manually reconstructing table lineage.

## Functional requirements

1. Detect open Job and Pipeline failures from native system tables.
2. Clear an incident when a newer successful run or refresh is observed.
3. Resolve direct table dependencies, Job-to-Pipeline triggers, and table-update triggers.
4. Traverse downstream dependencies to a configurable maximum of five hops.
5. Include Jobs, Pipelines, dashboards, Genie spaces, SQL queries, and alerts in the impact graph.
6. Preserve intermediate table or trigger evidence for each causal path.
7. Classify failures as likely root or likely cascade using dependency reach and failure timing.
8. Display the largest scoped blast radius by default.
9. Identify downstream owners and explicitly surface unresolved ownership.
10. Rank dependency hubs by downstream reach/out-degree and authorities by in-degree.
11. Support focused upstream/downstream exploration around any asset.
12. Report graph snapshot freshness and coverage quality.

## Non-functional requirements

- Incident triage must use scoped server-side queries rather than loading the full graph.
- Node identity must include entity kind.
- Graph traversal must be cycle-safe and depth-bounded.
- App deployment must be workspace/user portable.
- Empty, loading, error, and stale states must be explicit.
- Documentation and screenshots must match the current implementation.
- Anonymous demo data must be opt-in and unavailable in production unless explicitly enabled.
